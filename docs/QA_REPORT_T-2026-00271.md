### 阻塞性 Bug

**BUG-1: 路由冲突 — 服务器无法启动**

`apps/api/src/modules/projects/index.ts` 和 `apps/api/src/modules/indexes/index.ts` 同时注册了相同的路由：
- `GET /api/projects/:projectId/indexes`
- `GET /api/indexes/:indexId/status`

Fastify 在启动时抛出 `FST_ERR_DUPLICATED_ROUTE`，服务器直接崩溃，**无法启动**。

修复方案：移除 `projects/index.ts` 中重复的路由定义（这些路由已存在于 `indexes/index.ts` 中）。修复后服务器正常启动。

- **场景**: 同一项目同时触发 3 次索引构建
- **结果**: 第一次成功后，后续 2 次均返回 `429 TOO_MANY_REQUESTS` ("Project currently indexing")
- **判定**: ✅ PASS — 并发控制生效

### 2. 非法输入 — 空组织名称
- **场景**: `POST /api/organizations` 发送 `{"name":"","slug":"testorg-b"}`
- **结果**: 返回 500，Zod 验证报错 `"String must contain at least 2 character(s)"`
- **判定**: ⚠️ PASS（功能正确，但错误处理不规范 — 返回 500 而非 400）

- **结果**: 返回 500，Zod regex 验证失败
- **判定**: ⚠️ PASS（功能正确，但应返回 400 而非 500）

### 4. 非法输入 — 缺少必填字段
- **场景**: 创建项目时缺少 `gitUrl`
- **结果**: 返回 500，Zod 验证报错 `"Required"`
- **判定**: ⚠️ PASS（功能正确，但应返回 400 而非 500）

### 5. 越权访问

- **场景 2**: 用户 B 尝试在用户 A 的团队中创建项目 → 403 ✅

## 发现的问题

### BUG-1 (严重): 重复路由导致服务器无法启动
- **位置**: `apps/api/src/modules/projects/index.ts` vs `apps/api/src/modules/indexes/index.ts`
- **影响**: API 服务器无法启动，所有功能不可用
- **原因**: 两个模块都注册了 `GET /api/projects/:projectId/indexes` 和 `GET /api/indexes/:indexId/status`
- **修复**: 已移除 `projects/index.ts` 中的重复定义

### BUG-2 (中等): Zod 验证错误返回 500 而非 400
- **位置**: 所有路由的 Zod schema 验证
- **影响**: 客户端无法区分内部错误和请求错误
- **预期**: 输入验证失败应返回 400 Bad Request
- **影响范围**: 组织创建、项目创建等所有端点

### BUG-3 (低): 邮箱注册不返回 JWT 令牌
- **位置**: `POST /api/auth/register`
- **影响**: 用户注册后需要额外的登录流程才能获取 token
- **预期**: 注册后应直接返回 JWT 令牌，或提供独立的登录端点

## 结论

### qa_passed: false

**原因**:
1. **BUG-1**: PR 引入的 server.ts 变更与现有代码存在重复路由冲突，导致 API 服务器无法启动。这是一个**阻塞性故障**，必须在 merge 前修复。
2. **BUG-2**: 输入验证错误处理不规范（500 vs 400），虽然不是阻塞性但应修复。

**建议**:
- 修复重复路由冲突后，重新进行完整验收
- 将 Zod 错误处理统一为返回 400
- 邮箱注册流程补充登录端点或注册后直接返回 token
