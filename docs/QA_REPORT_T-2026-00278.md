## 破坏性测试

### DT-01: 降级超限保护
- **检查**: 项目数 > 目标套餐限制时是否拒绝
- **结果**: ✅ PASS — 返回 422 + 详细错误消息
- **注意**: 仅验证项目数和成员数，未验证 maxSymbols（合理：符号数由索引系统控制）

### DT-02: 并发升级竞态
- **检查**: 同时两次 subscribe 请求
- **结果**: ⚠️ BLOCKED — API 无法启动，无法测试。代码使用 `upsert` 但无事务保护，可能产生竞态

### DT-03: Webhook 重放攻击
- **检查**: 相同 webhook 回调发送两次
- **结果**: ⚠️ 潜在问题 — 无幂等性保护。第一次更新 invoice 为 PAID，第二次可能重复处理
- **建议**: 检查 invoice.status 是否已为 PAID，跳过重复处理

### DT-04: 乐观升级风险
- **检查**: 订阅在支付前立即更新
- **结果**: ⚠️ 风险 — 用户升级后立即获得 Pro 权限，但支付可能失败
- **当前处理**: 支付失败时 status='PAST_DUE'，但用户已享受 Pro 功能
- **建议**: 考虑使用 pending 状态或在支付确认后才生效

### DT-05: 环境变量缺失
- **检查**: WECHAT_PAY_APP_ID, WECHAT_PAY_MCH_ID 等
- **结果**: ✅ 代码中有 `process.env` 引用
- **注意**: 本地开发环境未配置，实际支付调用会失败（这是预期的，本地开发不连接真实支付）

- ✅ Webhook 回调处理

**但存在阻塞性问题**:
1. **API 服务器无法启动** — 同 T-2026-00277 的模块解析问题
2. **Webhook 幂等性缺失** — 支付重复处理风险

### 修复建议

1. **修复 `packages/engine/package.json`** — 同 T-2026-00277 修复建议
2. **添加 Webhook 幂等性保护**:
   ```typescript
   // 在处理 webhook 前检查 invoice 状态
   if (invoice.status === 'PAID') {
     return reply.send({ received: true, ignored: true, reason: 'already_paid' });
   }
   ```
3. **考虑支付状态机**: 引入 `pending` → `paid` / `failed` 的明确状态转换
