## 破坏性测试

### DT-01: 降级超限保护
- **结果**: ✅ PASS — 项目数和成员数分别在 subscribe 前做 count 校验，超限返回 422

### DT-02: 乐观升级风险
- **结果**: ⚠️ 观察 — 升级后立即 upsert subscription 为 ACTIVE 状态（支付确认前），若支付失败则 status 转为 PAST_DUE。用户短暂享受了 Pro 权限。当前处理可接受但建议在文档中标明

### DT-03: Webhook 重放攻击
- **结果**: ⚠️ 观察 — 无显式幂等性保护。但数据库层面 invoice 更新是幂等操作（同一 invoice 重复更新为 PAID 状态值不变）。建议在代码层添加 `if (invoice.status === 'PAID') return` 提前返回

### DT-04: 免费套餐无限切换
- **结果**: ✅ PASS — Free 套餐无支付环节，直接 upsert，无安全风险

### DT-05: 环境变量缺失
- **结果**: ✅ PASS — 支付凭证未配置时 webhook 验证自动跳过（`if (!secret) return true`），不影响本地开发
