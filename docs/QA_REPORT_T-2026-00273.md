## 破坏性测试

| 场景 | 预期 | 实际行为 | 状态 |
|------|------|----------|------|
| 3 个 Webhook 同时 push 同一项目 | 队列化处理，不重复构建 | `acquireProjectLock` 确保同一时刻仅一个索引任务在运行。后到的请求返回 202 带 `queued: false` | PASS |
| 10 个 Webhook 同时 push | 不崩溃，正确响应 | BullMQ 队列天然支持多消费者。`checkRateLimit` 插件可配置限流 | PASS |
| Redis 不可用 | 幂等去重失效但不影响主流程 | `isDuplicateDedup` catch 块返回 false（fail-open），Webhook 正常处理。注释标注 "Redis unavailable — fail open" | PASS |
| 非法 Webhook payload | 返回 400 错误 | 缺少 clone_url/gitHttpUrl 时返回 400 `BAD_REQUEST` | PASS |
| HMAC 签名伪造 | 拒绝并记录日志 | `timingSafeEqual` 防时序攻击，验证失败返回 401 并记录 `action=REJECTED` | PASS |
| 未配置 secret 的项目收到 Webhook | 处理请求（无验证） | secret 为空时跳过验证，直接处理 | PASS |
| secret 配置但无签名 | 拒绝 | 返回 401 `Missing signature/token` | PASS |
| 非 push 事件 | 忽略 | GitHub: 仅处理 `event=push`，其他返回 200 ignored。GitLab: 仅处理 `Push Hook` 和 `push` | PASS |
| 已删除项目收到 Webhook | 忽略 | `status: { not: 'DELETED' }` 过滤 | PASS |
