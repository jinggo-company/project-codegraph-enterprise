## 破坏性测试

### DT-01: 双通道容错
- **检查**: `Promise.allSettled` 确保一个通道失败不影响另一个
- **结果**: ✅ PASS — 正确实现

### DT-02: Webhook URL 缺失
- **检查**: 环境变量未配置时的行为
- **结果**: ✅ PASS — `if (!webhookUrl) return false;` 静默返回
- **注意**: 企微和钉钉是独立检查，一个有 URL 一个没有时仍可正常工作

### DT-03: 钉钉签名时间戳
- **检查**: HMAC 签名的 timestamp 使用 `Date.now()`
- **结果**: ✅ PASS — 签名在发送时动态生成
- **注意**: 钉钉要求 timestamp 在 ±5 分钟内，当前实现满足要求

### DT-04: 通知重试
- **检查**: 通知发送失败后的重试机制
- **结果**: ❌ FAIL — 无重试逻辑。`fetch` 失败或 `errcode !== 0` 直接返回 `false`
- **建议**: 添加指数退避重试（最多 3 次）

### DT-05: 通知频率控制
- **检查**: 同一项目短时间内多次构建的通知限制
- **结果**: ❌ FAIL — 无去重/限频机制。如果 CI/CD 频繁触发（如 10 次 push），会发送 10 条通知
- **建议**: 添加通知聚合或限频（如 5 分钟内最多 1 条/项目）

## 结论

### qa_status: qa_failed

F8 企微/钉钉集成代码实现**逻辑正确且完整**，覆盖了 PRD AC-10 的所有核心要求：
- ✅ 企微 Markdown 通知（构建成功/失败/用量/审批）
- ✅ 钉钉 Markdown 通知 + HMAC 签名
- ✅ 双通道并行发送 + 容错
- ✅ 审计日志自记录
- ✅ 用量告警封装

**但存在阻塞性问题**:
1. **API 服务器无法启动** — 同 T-2026-00277 的模块解析问题
2. **无通知重试机制** — 网络波动时通知可能丢失
3. **无通知限频** — 频繁构建时可能产生通知轰炸

### 修复建议

1. **修复 `packages/engine/package.json`** — 同 T-2026-00277 修复建议
2. **添加通知重试**:
   ```typescript
   async function sendWithRetry(url: string, body: string, retries = 3): Promise<boolean> {
     for (let i = 0; i < retries; i++) {
       try {
         const res = await fetch(url, { method: 'POST', ... });
         if (res.ok) return true;
       } catch { /* retry */ }
       await sleep(Math.pow(2, i) * 1000);
     }
     return false;
   }
   ```
3. **添加通知限频**: 使用 Redis 存储最近通知时间，5 分钟内不重复发送
