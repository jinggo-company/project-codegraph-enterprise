## 破坏性测试

### DT-01: 审计日志不可篡改
- **检查**: `registerAuditModule` 中只有 `app.get` 路由
- **结果**: ✅ PASS — 无 PUT/PATCH/DELETE 路由
- **注释确认**: 代码含 `// Explicitly: no PUT/PATCH/DELETE routes for audit logs — they are immutable`

### DT-02: 审计写入失败不阻塞主流程
- **检查**: `apps/worker/src/jobs/build-index.ts` 构建失败后的审计日志写入
- **结果**: ✅ PASS — 外层 `try/catch` 包含 `console.error`，不抛出异常
- **注意**: Webhook 审计写入也有独立的 `try/catch` 保护

### DT-03: 导出上限保护
- **检查**: `take: 10_000` 硬编码上限
- **结果**: ✅ PASS — 防止恶意请求导出海量数据
- **建议**: 上限值应可配置（环境变量），当前为硬编码

### DT-04: CSV 注入防护
- **检查**: `csvEscape()` 函数
- **结果**: ⚠️ FAIL — 缺少对 `=` 和 `+` 开头的值的前缀保护（CSV 注入/CVE-2023-xxxx 类攻击）。当前只处理了 `,` `"` `\n`
- **建议**: 对 `=` `+` `-` `@` 开头的值添加 `\t` 前缀或单引号

### DT-05: 多租户隔离
- **检查**: 审计日志查询使用 `organizationId: orgId` 作为 where 条件
- **结果**: ✅ PASS — 所有查询和导出都基于 organizationId 过滤
- **注意**: `orgId` 来自 URL 参数 `:orgId`，应验证请求用户确实属于该组织（需检查 `authenticate` 中间件逻辑）

### 修复建议

1. **修复 `packages/engine/package.json`**:
   ```json
   {
     "main": "./dist/index.js",
     "types": "./dist/index.d.ts"
   }
   ```

2. **增强 `csvEscape()` 函数**:
   ```typescript
   function csvEscape(value: unknown): string {
     if (value === null || value === undefined) return '';
     const str = String(value);
     // CSV injection prevention
     if (str.startsWith('=') || str.startsWith('+') || str.startsWith('-') || str.startsWith('@')) {
       return `'${str}`;
     }
     if (str.includes(',') || str.includes('"') || str.includes('\n')) {
       return `"${str.replace(/"/g, '""')}"`;
     }
     return str;
   }
   ```
